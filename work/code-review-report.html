2. 安全审查

高危 密码重置端点缺少速率限制，存在暴力枚举风险 AuthController.java:40-53 / SecurityConfig.java:44

/api/auth/reset-password 被 permitAll() 放行，但其 resetPassword 方法未调用 LoginAttemptService.requireAllowed。虽有 MessageDigest.isEqual 防时序攻击，但攻击者可对 recoveryToken 进行不受限高频尝试。

修复：在 resetPassword 入口加入 loginAttempts.requireAllowed(request.username(), request.getRemoteAddr())，失败时调用 loginAttempts.failed(...)，成功后 succeeded(...)。
中危 密码强度校验缺失，可设置空密码 AccountService.java:53-68, 70-80

changePassword 与 resetPassword 仅校验新密码 UTF-8 长度 ≤72 字节，未校验最小长度/复杂度。encoder.encode("") 会成功，意味着可设置空字符串或 1 位弱口令。

修复：在 DTO 上加 @Size(min=8, max=72) 与 @Pattern（要求含字母+数字），或抽取 PasswordPolicy.validate(newPassword) 统一校验。
低危 SetupController 已初始化后跳过 token 校验 SetupController.java:31

if (!setup.initialized()) requireSetupToken(...) 意味着系统初始化后再次 POST /api/setup/initialize 不再校验 token。虽然 SetupService.initialize 会抛 conflict，但语义上应统一鉴权。

修复：将 requireSetupToken(suppliedToken) 提至 if 之前无条件执行，或至少在已初始化分支返回 409 前也校验 token。
通过 敏感信息保护良好
  • .env 含 DB_PASSWORD、PASSWORD_RESET_TOKEN，但已被 .gitignore 正确排除，git ls-files 确认未跟踪
  • 仅 .env.example 入库，符合 AGENTS.md 约定
  • 密码使用 BCryptPasswordEncoder(12)，强度足够
  • 日志仅记录 username，不泄露密码（AccountService.java:67,79）

3. 后端代码质量

中危 DashboardService 存在冗余查询与潜在 N+1 DashboardService.java:34-50

第 35 行已通过 current.user(auth) 取得 User，第 48 行又调用 accounts.me(auth)（会再次查 user+partner+couple）。此外单事务内连续调用 memoryService.list、anniversaryService.list 等子服务，每个发起独立查询，存在 N+1 倾向。

修复：复用已查得的 user，将 accounts.me(auth) 替换为本地 new MeResponse(views.user(user), views.user(partner), views.couple(user.getCouple()))。对子服务查询考虑批量预取。
低危 LoginAttemptService 内存存储重启即失效 LoginAttemptService.java:26

使用 ConcurrentHashMap 内存存储登录失败计数，进程重启锁定状态丢失。类注释已明确"为双人本地应用设计"，可接受，但建议在注释中再强调多实例部署下需替换为 Redis。

通过 分层与安全实践到位
  • 控制器全部经 Service 访问数据，无直连 Repository
  • SQL 全部使用 @Query 命名参数，无字符串拼接，无注入风险
  • 18 处 @RequestBody 均带 @Valid，Bean Validation 覆盖完整
  • Service 写方法均有 @Transactional
  • GlobalExceptionHandler 统一异常处理，含兜底 Exception
  • Session fixation 防护（migrateSession）、CSRF Cookie 仓库、CORS 配置完善

4. 前端代码质量

低危 4 个组件过大，需拆分 MemoriesView.vue 574行 / NotificationsView.vue 438行 / CalendarView.vue 397行 / ReportsView.vue 347行

单一组件承担过多职责。如 MemoriesView.vue 同时管理时间线、地图、相册三块逻辑。

修复：按职责拆为子组件（如 MemoryTimeline.vue、MemoryMap.vue、MemoryAlbum.vue），提取可复用 composable。
低危 AppShell 存在未捕获的 Promise AppShell.vue:28-29

handleSync 中 refreshUnreadCount() 与 bootstrapAuth(true) 未 await/未 catch，若 bootstrapAuth 抛错会成为未捕获 rejection。

修复：await bootstrapAuth(true).catch(() => {}) 或在函数内 try/catch。
低危 硬编码外部 URL 与魔法数字 MemoriesView.vue:324,321,342 / utils.ts / notifications.ts:69

OpenStreetMap 瓦片地址硬编码；字节换算、轮询间隔、地图中心坐标等魔法数字散落。

修复：地图 URL 迁至 .env（VITE_MAP_TILE_URL）；魔法数字提为命名常量；formatBytes 迁入 utils.ts。
通过 前端类型安全与防 XSS 优秀
  • 全代码库零 any/as any/v-html 使用
  • 纯 <script setup lang="ts">，无 Options API 混用
  • tsconfig 启用 strict、noUnusedLocals、noUnusedParameters
  • 错误处理规范：client.ts 统一 ApiError + errorMessage()，视图层普遍 try/catch
  • CSRF 双重 token 机制完善（client.ts:38-69）

5. 配置与依赖

低危 前端 package.json 缺少 lint/type-check 脚本 frontend/package.json

仅 dev/build/preview，无独立 lint、test、type-check 脚本，无 ESLint 配置。AGENTS.md 也注明前端无测试 runner。

修复：新增 "type-check": "vue-tsc --noEmit"；引入 ESLint + @vue/eslint-config-typescript；可选加 Vitest。
低危 会话超时 30 天偏长，上传上限偏大 application.yml:19-20,29

session timeout 30d 偏长（双人本地应用可接受，但建议 7d）；multipart 单文件 200MB / 总请求 220MB 偏大，media-total-max-bytes 2GB，注意磁盘与内存压力。

通过 依赖与版本管理
  • Spring Boot 4.1.0（2026 较新版本），依赖全部继承 parent BOM，无版本硬编码
  • 无识别出的已知漏洞依赖版本
  • open-in-view:false、ddl-auto:validate、server.address:127.0.0.1 默认安全
  • application-prod.yml 启用 forward-headers、cookie secure=true
